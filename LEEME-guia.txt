LA CASA DEL JUDOKA - GUÍA PARA PUBLICAR LA APLICACIÓN
====================================================

La aplicación está hecha con React y Vite. Firebase guarda las cuentas, las
publicaciones, las búsquedas y las opiniones. Esta guía explica cómo preparar
una publicación nueva; no hace falta editar el código para pegar credenciales.

IMPORTANTE
----------
- No compartas contraseñas ni archivos de credenciales de Firebase.
- La configuración de Firebase para la web se guarda en variables de entorno.
  La clave web no es una contraseña, pero no se deben subir archivos .env.local
  al repositorio.
- El modo de desarrollo se conecta siempre a emuladores locales; no modifica
  Firebase real. Las reglas de `firestore.rules` son la versión usada por el
  emulador y por la guía de despliegue: no se mantienen copias paralelas.
- No publiques la aplicación ni cambies reglas, dominios o planes de pago sin
  la aprobación de la persona responsable.

PARTE 1 - PREPARAR FIREBASE
---------------------------
Si ya existe un proyecto Firebase para la aplicación, usá ese mismo proyecto.
Si no existe, antes de crear uno pedí autorización a la persona responsable.

En Firebase Console:
1. Abrí el proyecto aprobado y agregá o seleccioná una app web (ícono </>).
2. En la configuración de la app copiá los valores apiKey, authDomain,
   projectId, storageBucket, messagingSenderId y appId.
3. En Authentication, activá el acceso por correo electrónico y contraseña.
4. Confirmá que Firestore esté habilitado en la región elegida por la persona
   responsable.

No pegues valores en archivos fuente. En una copia local del repositorio,
creá `.env.local` a partir de `.env.example` y completá estas variables:

- VITE_FIREBASE_API_KEY
- VITE_FIREBASE_AUTH_DOMAIN
- VITE_FIREBASE_PROJECT_ID
- VITE_FIREBASE_STORAGE_BUCKET
- VITE_FIREBASE_MESSAGING_SENDER_ID
- VITE_FIREBASE_APP_ID

El archivo `.env.local` está excluido de Git. No lo envíes por correo ni lo
copies a un issue o conversación pública.

PARTE 2 - DESARROLLO LOCAL
--------------------------
Instalá Node.js 22 LTS y abrí una terminal en la carpeta del proyecto.

En una terminal ejecutá:
  npm install
  npm run emulators

Dejá esa terminal abierta. En otra terminal, desde la misma carpeta, ejecutá:
  npm run dev

La aplicación local se conecta automáticamente a los emuladores Auth y
Firestore en `127.0.0.1`; el identificador usado es `casa-del-judoca-dev`.
La configuración local no envía cambios a Firebase real. Para apagar los
emuladores, usá Ctrl+C en la terminal donde se iniciaron.

Para compilar la aplicación:
  npm run build

Se genera la carpeta `dist/`. La compilación no sustituye la revisión manual
ni confirma que las credenciales, reglas o flujos estén bien configurados.

PARTE 3 - REVISAR SEGURIDAD ANTES DE PUBLICAR
---------------------------------------------
Antes de publicar, la persona responsable debe revisar:
- Las reglas actuales de `firestore.rules` y el comportamiento esperado.
- Los dominios autorizados de Firebase Authentication.
- Las restricciones de la clave web y App Check.
- La política de privacidad y el tratamiento de datos personales.
- El estado de las publicaciones pendientes y la privacidad de las fotos.

`firestore.rules` es la única fuente de verdad; no la reemplaces por una
del proyecto real. Las reglas de Storage también requieren revisión. Consultá
`docs/SEGURIDAD.md`, `docs/PLAN_FOTOS_STORAGE.md` y `docs/ACCESIBILIDAD.md`.

PARTE 4 - PUBLICAR LA APLICACIÓN
--------------------------------
La publicación requiere aprobación de la persona responsable. El proveedor de
hosting debe tener configuradas las seis variables `VITE_FIREBASE_*` de la
Parte 1. Configurá el comando `npm run build` y la carpeta de salida `dist`.
Podés usar Firebase Hosting u otro proveedor compatible con una aplicación
Vite. Para rutas internas, el hosting debe redirigir las solicitudes a
`index.html`.

No ejecutes `firebase deploy` desde una máquina local sin confirmar el proyecto
activo, revisar las reglas y recibir autorización expresa. Después de publicar,
la persona responsable agrega el dominio de producción a los dominios
autorizados de Firebase Authentication.

PARTE 5 - CUENTA ADMINISTRADORA
-------------------------------
La autorización de administración no se basa en una lista en `src/config.js`.
El acceso se define con el custom claim `admin` del usuario autenticado; la
persona responsable debe asignarlo con `scripts/set-admin-claims.mjs` y luego
pedirle a cada administrador que cierre sesión y vuelva a ingresar.

Cuando la aplicación esté publicada y aprobada:
1. La persona responsable identifica la cuenta administradora.
2. Ejecuta el script de claims en el entorno correcto para poner `admin: true`.
3. La cuenta cierra sesión y vuelve a ingresar.
4. Comprueba que aparezca el panel de administración.

QUÉ CAMBIÓ
----------
- La interfaz ahora está formada por componentes React; ya no depende de
  `src/legacy.js` ni `src/page.html`.
- Firebase se importa como dependencia npm y su configuración se lee de
  variables de entorno.
- El modo de desarrollo usa emuladores locales. No uses cuentas o datos reales
  para probar.
- Los datos se mantienen en Firestore; las fotos todavía se guardan como
  imágenes reducidas dentro de los documentos (hasta cuatro por publicación).
  Consultá `docs/PLAN_FOTOS_STORAGE.md` antes de cambiar ese diseño.

LÍMITES Y PENDIENTES
--------------------
- La validación con lector de pantalla debe hacerla una persona; hay un guion
  en `docs/ACCESIBILIDAD.md`.
- Las reglas propuestas necesitan verificación en emuladores antes de
  considerarlas para producción.
- Las publicaciones pendientes, la privacidad de fotos, las opiniones y el
  tratamiento de datos requieren una revisión de seguridad y privacidad.
- Los pagos con comisión automática todavía no están implementados; requieren
  un servidor que proteja las claves secretas.
- Esta guía no es asesoramiento legal. Consultá a una persona profesional sobre
  la Ley 25.326 y la política de privacidad.
